TITLE:
User generated autonomous digital token system

TYPE:
US Patent

ABSTRACT:
A digital token system and methods to provide user generated digital tokens includes receiving from a plurality of users authorization to create one or more unique tokens without approval from a central authority, wherein each user who created the unique token (“creator”) is the only user authorized to increase quantity of the same token-type; and rendering the quantity of each token type visible to recipients of the token.

CLAIMS:
1. A method to provide user generated digital tokens, comprising
receiving at a computer a request from any of a plurality of users authorization to create one or more unique tokens without approval from a central authority, wherein each user who creates a unique token (“creator”) having a predetermined token-type is the only user authorized to increase the quantity of the unique token with the same token-type; and
rendering by a processor the quantity of each token type visible to any other user or any recipients of the token.
2. The method of claim 1, wherein the supply of tokens is controlled by the creator of the token and cannot be manipulated by any government, bank, organization or individual.
3. The method of claim 1, wherein after creation, tokens are indestructible.
4. The method of claim 1, wherein tokens expire within a predetermined period after creation.
5. The method of claim 1, wherein after creation, each token is part of a set of tokens or token-type which has an identifier unique to the user.
6. The method of claim 1, wherein each user is uniquely identified by an identifier.
7. The method of claim 1, wherein tokens are electronic representations of quantities that exist on a centralized system on the network, and wherein once created tokens are indestructible, wherein tokens are only given away or exchanged in a transaction.
8. The method of claim 1, wherein the user elects to keep tokens in the user's possession, send tokens to another user, or trade tokens with another user in exchange for products or services.
9. The method of claim 1, wherein the user receives tokens from another user, accepts or rejects an offer of tokens from another user, requests tokens from another user, and honors or rejects request of tokens from another user.
10. The method of claim 1, wherein tokens represent real-world objects of value.
11. The method of claim 1, comprising rendering transactions untraceable or anonymous.
12. The method of claim 1, comprising rendering untraceable information on tokens quantity, circulation, creators and owners.
13. The method of claim 1, comprising determining the value of token by the creator, the owner, the user or combinations thereof.
14. The method of claim 1, comprising determining the value of any token or any token-type by a credibility of the creator through online feedback and ratings.
15. The method of claim 1, wherein the token has an expiration term.
16. The method of claim 1, comprising triggering an expiration term by an ownership change or by a location change.
17. The method of claim 1, wherein tokens in a digital form are instantiated into a physical form, comprising converting a physical form of tokens into a digital form.
18. The method of claim 17, wherein tokens in physical form have associated constraining attributes including (a) predetermined users who can make a claim, or (b) expiration attributes based on date, claiming, number of transaction, users and geography.
19. The method of claim 1, comprising enabling each of the plurality of users to create his or her own secure supply of unduplicatable digital tokens to allow each user to issue one or more private values or currencies.
20. A digital token system using a client server system where:
a centralized computer acting as a central synchronization point for all transactions among the different devices; and
computer readable code for a user to create unique tokens, wherein a user who created the token (“creator”) is the only user authorized to increase the quantity of tokens of the same token-type, wherein the outstanding number of token is visible to everyone.
21. A digital token system using a client server system where:
a plurality of computers each acting as a local synchronization point for all transactions among different devices; and
computer readable code on each computer to allow a user to create unique tokens, wherein a user who created the token (“creator”) is the only user authorized to increase the quantity of tokens of the same token-type, wherein the outstanding number of token is visible to everyone.
