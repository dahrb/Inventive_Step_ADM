CLAIMS

1. A method for suppressing the generation of a file access event by a kernel (204)
characterised by:

checking (S104, S106, S108) an in-kernel cache (206) to determine if data relating to
a file is within the in-kernel cache (206);

using the data relating to the file within the in-kernel cache (206) to determine (S109)
whether the file has been modified since a last time a file access event was generated for the
file; and

only the generating a file access event for a user-space component for the file where it
is determined that the file has been modified since the last time a file access event was

generated for the file.

2. The method of claim 1, wherein the step of checking an in-kernel cache (206) to
determine if data relating to the file is within the in-kernel cache (206) comprises determining

(S104) whether a vnode device for the file is within the in-kernel cache (206).

3. The method of claim | or claim 2, wherein the step of checking an in-kernel cache
(206) to determine if data relating to the file is within the in-kernel cache comprises

determining (S106) whether an inode for the file is within the in-kernel cache (206).

4, The method of any one of claims 1 to 3, wherein the step of checking an in-kernel
cache to determine if data relating to the file is within the in-kernel cache (206) comprises

determining (S108) whether an inode version for the file is within the in-kernel cache (206).

5. A method for initiating an antivirus application (208) employing the method of claim
1, wherein the antivirus application (208) is initiated for the file when a file access event is

generated (S110) for the file.
